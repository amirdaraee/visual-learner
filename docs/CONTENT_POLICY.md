# Content Policy

Visual Learner teaches. A page that looks great and teaches something wrong is worse than no page.

## Accuracy

- Every factual claim must be something you can source. Keep a short list of sources in the pull request.
- Prefer primary or authoritative sources: textbooks, review articles, standards bodies, agency data, official guidelines.
- Mark approximate numbers with `~` or words like "about" and "typically". Do not give false precision.
- If a figure varies by lab, device, dataset or year, say so on the page.
- When a simplification is needed for teaching, label it ("simplified rules", "schematic") rather than presenting it as the whole truth.
- Invented examples, patients, circuits or measurements must be marked as invented. Never present made-up data as real.
- State the limits of a model. What does this simulation leave out?

## Visuals

- If a visual is not to scale, say so on the page.
- Colour and motion should carry meaning, not decoration.
- Keep a clear line between measured, simulated and illustrative.

## Safety and professional topics

Medical, electrical, chemical and aerospace topics carry real-world risk.

- Add a visible note that the page is educational and not professional advice.
- Never give step-by-step instructions that could cause harm if followed (for example, synthesising hazardous compounds, defeating safety interlocks, or working on mains-powered equipment).
- Medical topics must not suggest diagnosis or treatment decisions for an individual.

## Originality and attribution

- Write your own code, copy and artwork.
- Do not copy another site's source, layout or visual style. If a site states that it must not be reproduced without permission, do not reproduce it.
- Credit third-party data, images, equations and libraries on the page or in the pull request.
- Use only assets whose licence permits reuse, and record the licence.

## Privacy

- No analytics, cookies, fingerprinting or third-party embeds.
- No collection of user input beyond the page's own session. Do not store personal data.

## Accessibility

- Every control works with the keyboard and has a visible focus state.
- Respect `prefers-reduced-motion`.
- Text keeps readable contrast. Do not rely on colour alone to convey state.
- Provide a text explanation of what the scene shows, in the page's explain panel.

## Corrections

Spotted an error? Open an issue titled "Correction: <topic>" with the claim, the problem and a source. Corrections are fixed quickly and, for substantial ones, noted in the pull request.
